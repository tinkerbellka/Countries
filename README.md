# Приложение для просмотра стран (REST Countries) с личным слоем данных поверх API: локальные профили, избранное, заметки, коллекции, история просмотров и офлайн кэш

Что добавлено в финальной работе:

Новое в UI и навигации:

нижняя панель: Страны, Коллекции, История, Настройки;
экран настроек (профили, тема, приватность коллекций);
экран истории недавно просмотренных стран;
раздел коллекций с вкладками «Мои» и «Общие»;
фильтры на списке: все / избранное / с заметками;
баннер при показе данных из кэша без сети.

Новое в данных и логике:
локальные профили пользователей (без серверной авторизации);
PIN при входе в защищённый профиль;
кэш списка стран в Room с fallback при отсутствии сети;
WorkManager для фонового обновления кэша и предзагрузки избранного;
DataStore для настроек приложения (не для пользовательского контента).

Room:

Таблица-Назначение
user_profiles-Профили: имя, хэш PIN, флаг «показывать коллекции другим»
favourites-Избранное (привязано к profileId, время добавления)
cached_countries-Кэш ответов API для офлайн списка
view_history-История просмотров по профилю
country_notes-Личные заметки к странам
collections-Пользовательские коллекции
collection_countries-Состав коллекции (связь коллекция и страна)

DataStore (только настройки):
активный профиль;
тема (системная / светлая / тёмная);
сортировка списка;
TTL кэша и режим фоновой синхронизации (значения по умолчанию, без отдельного экрана в UI).

Заметки, история, коллекции и избранное в DataStore не хранятся.

Новые пользовательские сценарии:

1. Offline-first просмотр (существенный)
Пользователь хотя бы раз загружает список с сетью - данные попадают в cached_countries. Без интернета список читается из Room, показывается баннер. Детали страны при ошибке сети берёт данные из кэша или из записи в избранном. Сеть нужна для обновления, а не как единственный источник экрана.

2. Локальные профили (существенный)
На одном устройстве несколько пользователей: создание профиля, опциональный PIN, переключение с проверкой пина, удаление (кроме последнего). У каждого профиля своё избранное, история, заметки и коллекции. Новая сущность в модели — user_profiles и привязка остальных таблиц к profileId.

3. Коллекции и обмен между профилями (существенный + новая связь)
Пользователь создаёт коллекции, добавляет страны с экрана деталей, смотрит состав, удаляет элементы. В настройках можно включить «Показывать мои коллекции другим» - тогда другие профили на этом устройстве видят их во вкладке «Общие» (только просмотр, без редактирования чужих коллекций).

4. Заметки и история
На деталях - личная заметка к стране; она влияет на фильтр «С заметками» в списке. Просмотр деталки автоматически пишется в историю; с экрана «История» можно снова открыть страну или очистить историю профиля.

5. Избранное (как часть более сложной логики)
Не один toggle: избранное по профилю, фильтр «только избранное», офлайн-доступ, фоновая предзагрузка, использование данных избранного для деталки без сети.

Как устроен offline-first:
Принцип: локальные данные - основа UI, сеть - для обновления и синхронизации контента API

Список стран:
CountriesRepository.fetchCountries() сначала идёт в API;
при успехе - сохранение в cached_countries;
при ошибке сети - чтение из кэша, если он есть;
OfflineSyncPolicy проверяет свежесть кэша по TTL (из DataStore, по умолчанию 24 ч);
ViewModel показывает баннер, если источник - кэш.

Деталка:
при сети - API + снимок в кэш;
без сети - cached_countries или favourites по коду страны.
Всегда локально (без сети): избранное, коллекции, история, заметки, профили, общие коллекции других профилей.

Ограничения: первый запуск без интернета даст пустой список; новый поисковый запрос офлайн сработает только если такой запрос уже был закэширован.

Фоновая обработка (WorkManager)
Worker-Зачем
CacheRefreshWorker - Обновляет полный список стран в Room
FavouritesPreloadWorker - Подгружает детали избранных и обновляет кэш

Запуск при старте приложения (WorkScheduler), Constraints: сеть (по умолчанию - только wifi). Пользователь не обязан настраивать это вручую, офлайн работает за счёт уже сохранённых данных.
