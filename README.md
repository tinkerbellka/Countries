Countries Explorer (REST Countries) - приложение со списком стран, поиском, деталями и избранным.

## Room

Используется база данных Room `CountriesDatabase` с таблицей `favourites`.

Хранится:
- `code` (PK, код страны)
- `nameCommon`
- `region`
- `population`
- `capital`
- `flagPng`

Сценарий:
- Пользователь добавляет страну в избранное на экране списка.
- Данные страны сохраняются в Room.
- Экран избранного читает страны напрямую из Room.
- После перезапуска приложения избранное остаётся.

Проверка:
- Добавить 1-2 страны в избранное.
- Полностью закрыть приложение.
- Открыть снова и проверить, что страны остались в избранном.

## Домашнее задание 5 (Тестирование)

Сделано:
- Юнит-тестов: **11** (авторских)
- Интеграционных тестов: **6** (авторских: 3 data + 3 UI)
- Нетривиальных тестов: **6+**

Покрытые сценарии (юнит):
- корректное начальное состояние экрана (`Loading`);
- успешная загрузка списка;
- ошибка загрузки списка;
- `retry()` после ошибки инициирует новый запрос и переводит в `Success`;
- пустой результат поиска даёт `Empty`, а не `Success(emptyList())`;
- загрузка избранного из Room в `Success`;
- повторное добавление страны в избранное не создаёт дубль;
- корректное преобразование модели Room -> `Country`;
- успешная загрузка деталей;
- `retry()` на деталях повторно грузит тот же `id`.

Покрытые сценарии (интеграционные):
- `Repository + Room`: запись/чтение избранного;
- `Repository + Room`: отсутствие дублей;
- `Repository + Room`: удаление из избранного;
- UI: список -> клик по элементу -> переход на детали нужного `id`;
- UI: ошибка -> нажатие `Повторить` -> успешное состояние.

Flow/StateFlow/SharedFlow в проекте не используются, поэтому отдельные тесты на последовательности эмиссий для Flow не требуются.
